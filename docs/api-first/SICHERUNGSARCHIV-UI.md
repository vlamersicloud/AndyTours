# Vollarchiv-Erstellung: UI- und Journalstand

- Die UI ist über „Extras → Vollarchiv erstellen / fortsetzen…“ an ein Eigentümer-Modal angebunden. Es zeigt Status, Vorgangs-ID und geprüfte Archivmetadaten schreibgeschützt; Wiederherstellung, Download und Pfadauswahl sind nicht enthalten. Während der Arbeit ist Schließen gesperrt.
- Die Komposition verwendet ein backendbezogenes Journal unter `%LOCALAPPDATA%/AndyTours/Sicherungsjournal`, ohne Programmpfad-Fallback. Konstruktion und Dialogöffnung führen weder Journal-I/O noch POST aus; erst der explizite Befehl öffnet das Journal. Ein offener Vorgang wird mit derselben GUID über Fenster- und Anwendungsneustarts fortgesetzt.
- Die Erstellung verwendet den bestehenden HTTP-Client mit zehnminütigem Timeout. ViewModel, Dialog und Journal-Store sind vorhanden; UI-Strukturfixtures samt Quellressourcen sind vorbereitet/verknüpft, aber nicht ausgeführt. Kein UI-Laufzeit-, End-to-End- oder Wiederanlauftest.
- Das ViewModel hält die Journal-Lease während des Requests, bestätigt nur validierten Erfolg und aktualisiert nach Dispose keine Anzeige mehr. Stromausfall-/Filesystem-Durabilität ist keine absolute Garantie; externe Manipulation und TOCTOU werden nicht ausgeschlossen.
